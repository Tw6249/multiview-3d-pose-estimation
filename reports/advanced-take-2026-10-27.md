# AdvancedTake 验收（2026-10-27 起）

> **2026-10-29 目录调整**：旧主线（BRM‑C2，`pose_sim/`、`motion_control/` 等）已删除，本链路成为唯一方案。原 `standalone_sim_plan/` 拆为代码包 `g1_imitation/`（core、config、gmr_bridge）与根目录的 `scripts/`、`tests/`；配置文件改名为 `pipeline_config.json`，输出目录改为 `outputs/advanced_take/`，类名去掉 Standalone 前缀。下文中的“standalone”“旧主线”等称呼是当时的记录，保留原样；文中路径已按新结构替换。

范围：本链路的 S1–S6 直接处理 AdvancedTake 原始 RGB，并以 BVH 为参照。仿真，运动学/开源 RL 策略回放，**不是实机，也不是全身动作模仿成功率**。

## 做了什么

| 步骤 | 实现 | 输入 → 输出 |
|---|---|---|
| S1 | `advanced_take_s1_extract.py`，重新推理（RTMW‑m FP16 256×192 + 每帧 YOLOX，DETECT 模式），不复用旧缓存 | 8 个有效 Take × 4 机位 → 27 点 2D |
| 标定 | `advanced_take_calibrate.py`，**不含 BVH 的**针孔自标定（本质矩阵初始化 + 稀疏 BA，仅 Take_002/012 的 2D）；再用**一个 7 自由度相似变换**对齐 BVH 世界系（同样只用 002/012） | 内外参 + 度量尺度 |
| S2/S3 | 原样调用 standalone `MultiViewTriangulator` 与 `TemporalFilter`（规范参数，30 Hz） | 世界系 27 点轨迹 |
| 评估 | `advanced_take_s2s3_eval.py`，12 个躯干/四肢关节对 BVH；`core/adv_eval.py` | MPJPE、Procrustes、骨段方向角、关节角、骨长、抖动、时间偏移扫描 |

## 控制对照（SONIC v1.1，S4→S5→S6B，50 Hz）

standalone 的控制器已**全面换成 SONIC v1.1**（自包含适配器，与旧主线适配器逐步对齐，误差 ≤1e-9）：编码器 + 解码器 ONNX，策略自带 Kp/Kd，因果运行下把**当前**参考样本复制进全部 10 个窗口槽位（无未来预览）；S5 参考不经限幅直接输入。根部 XY/高度不是该策略的输入，步态只能来自关节参考（腿/骨盆朝向）。TWIST2 的同一套实验保留为基线（`control/selfcal_twist2/`）。

|---|---|---|---|
| 002 | 9.7 / 6.6 | 10.1 / 3.3 | 15.4 / 4.6 |
| 006 | 9.4 / 5.6 | 15.3 / 4.6 | 27.5 / 3.9 |
| 007 | 11.6 / 12.1 | 18.7 / 6.1 | 32.3 / 6.5 |
| 008 | 11.7 / 10.1 | 18.6 / 5.1 | 33.8 / 5.1 |
| 012 | 9.4 / 11.8 | 80.6 / 42.7 | 39.4 / 24.6 |

- **SONIC：腿与 TWIST2 相当，手臂和手腕明显更不贴参考**（肩+肘 10–19° vs 3–6°；腕 15–34° vs 4–7°）。腕关节在 BVH12/视觉12 下没有朝向目标，属未观测自由度，不应计为跟踪失败；但肩/肘是被观测的。
- **根轨迹跟随大幅改善**：BVH12 臂的平均路径误差 SONIC 0.08–0.47 m，TWIST2 0.13–1.97 m；007 偏航累计 参考 372° / SONIC 363° / TWIST2 142°。SONIC 的步态来自关节参考，更贴合“步态来自源的腿部与骨盆运动”的目标。
- 总 RMSE（29 关节）SONIC 约为 TWIST2 的 2 倍（002/006/007/008 的 BVH12 臂：10.9–19.7° vs 4.7–9.0°）；但表中已显示这是手臂/手腕差异，不是腿。滞后不是主因（逐关节最优滞后 80–120 ms 只把 RMSE 降 <1°）。
- **视觉带来的额外误差远小于控制器本身的跟踪误差**：物理关节角对 BVH 参考的 RMSE，视觉12 比 BVH12 只多 0.2–3.8°（SONIC）/ 0.8–4°（TWIST2）。
- 视觉12 与 BVH 参考的 G1 关节角分歧（与控制器无关，同一份 S5 输出）：腿 3–8°，腰 5–7°，臂 7–11°（Take_012：视觉12 右臂 67°，视觉12+S3 双臂 58–68°，原因未核实）。
- 视觉27（加入脚/手地标）使手臂分歧升至 28–37°：**不能判定为错误**，因为 BVH12 参考没有手腕朝向目标；手/脚朝向准确度**未评估**。
- 12 点臂 6A 脚滑 0.000 是**空洞值**：踝高始终高于 5.5 cm 阈值，脚悬浮约 4 cm，从未判定为支撑；27 点臂脚落地后滑移 0.1–0.44 m/s（运动学回放）。
- 视觉12（未滤波）的偏航角速度噪声大（TWIST2 实验中越界 130/578 帧，S3 降到 31）；SONIC 不使用速度指令，不受该项影响。
- standalone 自带 10 组动作验收（合成人体动作）：SONIC 下存活 10/10、支撑脚滑移均值 0.0057 m/s，但 `06_torso_twist_arm_wave` 关节 RMSE 0.139 rad 超过 0.12 rad 阈值（TWIST2：0.082），记为 strict XFAIL，阈值未改。真实视频端到端（MPI‑INF‑3DHP，无 3D 真值）SONIC 存活，关节 RMSE 0.525 rad（TWIST2 0.111 rad）。
- 与旧主线（BRM‑C2 + SONIC/TWIST2）不是同一实现：同一视频，旧线 TWIST2 在 008 倒、012 存活，本线 TWIST2 在 012 倒、008 存活。**结果随重定向器改变**，策略不是唯一决定因素；两线物理平台/参考管线不同，不是严格对照。

## 纯 RGB 链路（2026-10-28 补充）

目标：从 4 路 RGB 到 G1 物理仿真，链路内不使用 BVH；BVH 只在最后离线打分。

**配准**（`advanced_take_rgb_register.py`）：保留无 BVH 的 BA 内参与相对位姿，删去 BVH 相似变换。重力和地面来自每帧最低脚跟/脚趾点的 RANSAC 平面拟合：870 个候选，861 个内点，残差中位 5.8 mm。尺度来自骨盆高度先验 0.92 m（配置 `default_human_pelvis_height_m`），**这是对受试者的假设，不是测量**。偏航和原点是约定。

**离线对 BVH 打分**（`advanced_take_rgb_eval.py`，留出 006/007/008）：

| 指标 | 006 / 007 / 008 |
|---|---|
| 重力方向误差 | 0.44° / 0.17° / 0.05° |
| 尺度偏差（先验所致） | +4.9% / +4.1% / +5.0% |
| 平均高度偏差 | +7 / −4 / +1 mm |
| 只对齐偏航和水平原点后的 MPJPE | 41.8 / 51.4 / 42.8 mm（BVH 配准时为 36.0 / 38.2 / 32.5） |
| 整段 Procrustes MPJPE | 35.4 / 37.5 / 31.8 mm（与 BVH 配准时相同） |

**发现并修复的三处世界系依赖**（不改任何权重、阈值或物理参数）：

1. **S5 起步：** IK 从世界原点出发。纯 RGB 世界系下，Take_007、008、012 的左臂收敛到镜像分支（肩偏航 +126° 对 −52°，腕横滚 −100° 对 +82°），并保持整段，Take_012 因此倒地。修复：从第一帧骨盆目标的位姿起步（实验脚本 `run_chain`）。
2. **S5 核心：** 只有位置的目标（膝、肘，以及无朝向观测的腕和踝）带的是世界单位旋转。Mink 的 SE(3) 对数把旋转误差耦合进平移误差，所以朝向代价虽为 0，关节解仍随世界偏航变化：偏航 130° 时差 2.9°。修复：位置目标改为携带当前 FK 旋转（`s5_mink_ik.py::_update_task_targets`）。修复后，偏航加平移下的关节差为 1e-11°，由新增的 `test_world_convention_invariance.py` 覆盖。
3. **S6 起步：** 机器人以偏航 0 生成，而纯 RGB 世界系里第一帧朝向约为 −140°。0.5 s 的起步阶段转不完，留下 20–34° 的物理偏航误差。修复：把 S5 根轨迹换到第一帧的朝向和地面位置（`anchor_heading`），关节角不变。

| 006 | 是 | 11.7° | 20.0° | 12.9, 10.9 / 6.8 / 35.6, 30.0 | 0° / 5° |
| 007 | 是 | 18.8° | 19.0° | 13.8, 13.8 / 7.2 / 33.1, 22.3 | 369° / 366° |

- 两套世界系（BVH 配准与纯 RGB）下的关节参考差 1.3–2.5° RMS，来自约 5% 的尺度差和配准残差。
- 视觉参考的根路径比 BVH 的长（006：3.7 m 对 1.8 m），说明骨盆抖动被当成了位移。物理根路径只有参考的 40–55%。
- 修复后，**Take_012 的 BVH 驱动组倒地**（倾角 97.6°），视觉组存活。修复前 BVH 组存活，说明 012 处在 SONIC 稳定性的边缘，存活与否对参考的小变化敏感。
- standalone 10 组合成动作在 S5 修复后：存活 10/10，06 号动作 0.138 rad（修复前 0.139），仍为 strict XFAIL。
- 视频 `video/<Take>_rgb_control.mp4` 只画 RGB、视觉骨架和 G1，不含 BVH。

**本节的限制：** 尺度靠先验，受试者身高与先验不符时根平移按比例偏差；S4 用受试者自身腿长归一化，所以关节参考受影响较小。相机同步仍是末帧对齐假设。BVH 配准的四组对照（`control/selfcal`）是 S5 修复前的结果，未重跑 vis12 两组。

## 第三方重定向：EasyMocap SMPL-X 拟合 + GMR（2026-10-28 补充）

目的：用通用、开源的标准重定向替换自写的 S4/S5。感知（S1–S2、纯 RGB 配准）和控制（SONIC）保持不变。

**链路：** 纯 RGB 27 点 → EasyMocap `smpl_from_keypoints3d`（默认权重）拟合 SMPL-X → GMR（`smplx` → `unitree_g1`，默认参数）→ SONIC。参考组为 BVH → GMR（`bvh_nokov`，原生 120 Hz）→ SONIC。

**版本与许可：**
- GMR `25f56db`，MIT 许可，只取了代码和 G1 资产。
- EasyMocap `e6006fd`，Project Registration License：研究、评估用途免登记；机构项目使用需先登记。
- smplx `1265df7`。
- SMPL-X 模型来自 v1.1 下载包（包内 `version.txt` 写的是 1.0），SMPL-X 模型许可，不入库。

以上都装在独立环境 `venv-py311-gmr`，standalone 和 CUDA 环境未改动。

**格式适配**（不改任何拟合或 IK 代码）：

## GMR 设为默认、删除 S4/S5（2026-10-28）

按用户决定，standalone 的默认重定向改为 `core/s45_gmr_retarget.py`（EasyMocap SMPL-X 拟合 + GMR）。实现方式是子进程调用独立环境里的 `gmr_bridge/worker.py`。自写的 `s4_se3_scaling.py`、`s5_mink_ik.py` 及其测试已删除。合成人体函数原样移到 `core/synthetic_human.py`；`world_registration.pelvis_height_prior_m` 和 `s6_closed_loop.mjcf_relative_path` 从旧 S4 配置迁出。

## 实时因果重定向：关键点直接 IK（2026-10-28）

动机：EasyMocap SMPL-X 拟合需要整段优化，非因果，单帧 0.12–0.26 s，无法满足"人动作到机器人跟踪 ≤ 0.2 s"。新模块 `g1_imitation/core/s45c_keypoint_ik.py` 不用人体模型，逐帧把 27 个关键点直接映射为 G1 参考；SMPL-X + GMR 保留为离线对照。

**方法**
- 标定：取开头 0.5 s 有效帧，求人体腿骨长度的中位数，得到根部位移缩放 s = G1 腿长 / 人腿长。标定期间输出默认站姿（朝向取髋线），标为未观测；之后用 0.5 s 线性过渡到重定向结果。
- 方向迁移：每段肢体（大腿、小腿、上臂、前臂）沿人体对应段的方向，长度用 G1 自身尺寸。
  - 骨盆的偏航/横滚取髋线；
  - 躯干姿态取肩线和髋→肩轴；
  - 脚的姿态取脚跟、大脚趾、小脚趾；
  - 手的姿态取手腕和食指、小指掌指关节。
- IK：Mink 微分 IK（DAQP），以上一帧为初值，每帧 3 步迭代，强制关节限位。
- 时间：只用当前帧和过去状态。`test_prefix_is_independent_of_future_frames` 逐位验证前缀不受未来帧影响。
- 缺失数据：缺某个肢体时，该肢体保持上一帧方向；缺躯干点时整帧保持、dq=0。缺失数据不会成为新动作。

**假设（不是测量）**
- 两个髋点测不出骨盆俯仰。躯干前倾由骨盆（髋关节）和腰按 `pelvis_trunk_share = 0.5` 分担。
- G1 手腕零位视为解剖中立位。
- 伸直时的上臂/腿扭转不可观测，由弱姿态项拉回默认站姿。
- 根部高度设为使机器人最低脚底点等于人脚底离地高度，保留腾空。根部位置不是 SONIC 的输入。

所有权重在闭环评测前确定，未按验收指标调参。

**延迟**（单进程，2085 个真人 30 Hz 帧）：单帧求解中位数 2.5 ms，p95 10.3 ms，最大 12.9 ms，小于 33 ms 帧间隔。链路延迟的主要构成：
- S3 One-Euro 滤波滞后：相对 S2 原始点 0–3 帧，典型 2 帧，约 67 ms；
- 30 Hz 采样到 50 Hz 控制的保持：平均约 17 ms；
- SONIC 预览延迟 D。

S1/S2 的计算时间这次没有测。

## 关键点 IK 设为默认重定向（2026-10-29）

上一节结束时留下 4 项待办：查 Take_012、统计 IK 收敛、重测 S6 验收、写明假设。全部完成后，默认 S4+S5 由 SMPL-X + GMR 换为关键点 IK；GMR 保留为离线参照（`solve_gmr_trajectory_from_3d`，`run_full_simulation_demo.py` 仍用它）。本节数字均来自本节修改后的最终代码，上一节的表格对应修改前的版本。

**1. Take_012 原始输入手臂误差 34° 的原因与修复**
- 分解方法：把机器人参考与 BVH 的方向误差拆成"输入关键点 vs BVH"（感知）和"机器人 vs 输入关键点"（重定向）。Take_012 原始输入的左上臂：感知误差 11.3°，重定向误差 32.6°；滤波输入的重定向误差只有 11.4°。问题在重定向。
- 根因：手的姿态（手腕 + 食指/小指掌指关节）原来是整条手臂共同参与的 IK 任务。原始输入的掌指关节噪声能把手的坐标系翻转近 180°，IK 为了满足它把肩和肘拉进错误的分支，并在之后持续停留。
- 修复：手的朝向不再进入整臂 IK。实现了只转三个腕关节的解法（`wrist_iterations`）并做了三方对照（5 段真人、13 组合成）：

  | 手的朝向 | 真人 v1.1@0.1：RMSE / 终点偏差 | 合成存活 | 与 BVH 的方向误差（物理，手臂/腿；原始输入） |
  |---|---|---|---|
  | 整臂任务（原） | 0.157 / 0.24 m（滤波）；0.236 / 0.71 m（原始） | 12/13 | 19.1 / 11.0，Take_012 34.2 |
  | 只转腕关节 | 0.171 / 0.33 m；0.198 / 0.54 m | 12/13 | 15.5 / 10.7，Take_012 16.9 |
  | 不跟踪 | 0.167 / 0.33 m；0.180 / 0.65 m | 13/13 | 15.2 / 10.9，Take_012 16.2 |

  只转腕关节时，腕部参考速度 p95 达到 330–1320 °/s（掌指关节噪声直接进了腕关节），肢体保真度与不跟踪相同。默认改为**不跟踪手的朝向**（`wrist_iterations = 0`，腕关节停在姿态项默认值）；手的朝向在 BVH12 里没有真值，无法验证哪个更接近人。这是看过结果后的选择，已在配置注释里写明。
- 顺带修了一处耦合：Mink 的位姿误差是 SE(3) 对数，即使朝向权重为 0，位置误差也会被当前朝向污染。现在膝、肘、腕三个纯位置任务每步迭代把目标旋转设为当前旋转，变成纯位置误差。单元测试 `test_default_ignores_hand_orientation` 验证翻转手的朝向后输出逐位不变（修前差 0.98°）。

**2. IK 收敛（3 步迭代是否造成隐藏滞后）**
- 对比 3 步和 50 步迭代：真人 10 组输入（5 段 × 滤波/原始）中，关节平均差 0.2–1.0°，与输入方向的误差相差 ≤ 0.4°；相对 50 步解的最佳时间偏移在全部 10 组上都是 0 帧。3 步没有造成滞后。
- 例外：Take_006 原始输入下 50 步解自己跳进了另一个分支（平均差 17°，p99 174°），3 步解反而更稳。这说明热启动 + 少步数本身有防跳变作用，但也说明解的分支不唯一。

**3. 单帧耗时的两个修正**
- 之前报告的 2.5 ms 中位数是在多线程 BLAS 下测的。IK 矩阵很小，多线程 BLAS 反而慢：同一输入 p50 12.6 ms；单线程 p50 1.7 ms。评测脚本现在在进程内固定 `OPENBLAS/OMP/MKL_NUM_THREADS=1`。
- 单线程下仍有成段的约 12 ms 慢帧，但其出现位置在重复运行时不同，且 IK 和非 IK 部分同时变慢；在空闲机器上重测消失。所以慢帧来自同时运行的其他评测进程，不是算法。空闲机器、单线程（4170 帧）：**p50 1.28 ms，p95 1.89 ms，p99 3.1 ms，最大 5.9 ms**。
