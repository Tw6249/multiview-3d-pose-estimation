# MAMMA 多人遮挡：S1b 多人跨视角关联与目标锁定（2026-10-29）

范围：只做感知层，不涉及动作域判断。`data/public_mamma_session` 共 120 帧（4 s），4 机位，户外。场景是两人推搡，戴帽的 P0 被推倒后躺地，光头的 P1 全程站立，背景还有旁观者。**这段数据没有 3D 标注**，下文都是一致性检查，不是精度。闭环部分是仿真（关键点 IK + SONIC v1.1），不是实机。

## 问题（改动前）

S1 在每个机位各自选一个框：DETECT 模式取面积×置信度最大的框，TRACK 模式取离 3D 重投影中心最近的框，机位之间没有身份约束。在 MAMMA 上：

- 只用 DETECT 选框（AdvancedTake 验收用的方式）时，四个机位裁到同一个人的帧只有 17/120。
- 在线 TRACK 链路跟随的是第 0 帧在 S2 共识里胜出的那个人。有 21 帧，其中一个机位裁到了另一个人。第 93–97 帧悄悄换了人，没有任何标记；第 93 帧的骨架是两人拼接的，离两个人都有 0.74 m。

## 新模块 S1b（`g1_imitation/core/s1b_person_association.py`）

位于 S1 和 S2 之间，S2 和 S3 不改；S1 只新增一个公开方法 `detect_person_candidates`。

| 项 | 内容 |
|---|---|
| 输入 | 每个机位的全部 YOLOX 人框，以及每个框上的 RTMW 27 点（`extract_person_candidates`）；P = K[R\|t]，世界坐标系 Z 朝上、单位米、地面 z = 0；帧时间（秒，严格递增） |
| 输出 | 目标在各机位的 27 点（只填被关联的机位，其余置信度为 0，直接作为 S2 输入）；`valid`、`status`、`target_id`、`selected_now`（为真时重置 S2、S3、S4+S5） |
| 1 分组 | 每帧穷举"每个机位选一个候选或不选"的组合，对 12 个躯干和四肢关节做 DLT 三角化。每个被采用的机位，中位重投影误差须 ≤ max(15 px, 0.03 × 框高)。组合得分为 Σ(1 − (误差/门限)²)，按贪心依次取出多个人 |
| 2 轨迹 | 用匈牙利算法把分组结果分配给 3D 轨迹，代价为关节距离中位数（按恒速预测），门限 0.25 m + 1.5 m/s × 未见时长。只有 ≥ 3 个机位看到的人才能新建轨迹，连续命中 3 帧后确认 |
| 3 目标 | 指定方式：操作者在某机位点选（像素），或给出世界 XY。也可以自动选，但只在相机环内恰好有一个已确认的人时才生效。锁定后不会转交给其他轨迹 |
| 失败行为 | 当帧没匹配上：OCCLUDED，0.5 s 后转 LOST。另一个人或另一条轨迹与目标匹配代价之差 < 0.10 m：AMBIGUOUS，0.3 s 后转 LOST。LOST 后，如果目标是指定的，只有重新指定才会再锁定。所有无效帧都给 S2 全零置信度，S2 输出 NaN，S3 保持上一帧 |
| 参数 | 写在 `pipeline_config.json` 的 `s1b_person_association` 段。初值在跑任何真实数据之前，按几何关系设定。只改过一次，依据是合成数据测试：两人沿某个机位视线前后对齐时，4 机位拼接组合的误差 10–26 px，能通过原先 0.06 倍框高的门限，于是相对门限改为 0.03，并加了 3 机位才能建轨的限制。真实数据上没有调过参 |

## 结果：MAMMA（操作者在 A001 第 0 帧点选目标）

| 指标 | 现有链路（S1 跟踪模式） | S1b 锁定 P1（站立） | S1b 锁定 P0（倒地） |
|---|---|---|---|
| 状态 | 无此概念 | TRACKING 118，UNSELECTED 2（轨迹确认期） | TRACKING 118，UNSELECTED 2 |
| 目标所用机位数 | 每帧 4 个（含裁错人的机位） | 118 帧都是 4 个 | 4 个 86 帧，3 个 11 帧，2 个 21 帧 |
| 躯干中心逐帧位移最大值 | **0.60 m**（超过 0.15 m 的有 5 帧） | 0.042 m | 0.063 m |
| 骨长变异系数最大值 | **62.7%**（右前臂），57.2%（左上臂） | 8.3% | 18.9%（髋宽，出现在 2 机位帧） |
| S2 重投影误差 中位 / P95 | 2.0 / 4.2 px | 2.1 / 4.5 px | 1.9 / 4.4 px |
| 目标躯干亮度 V（逐帧范围） | 90–162：前 93 帧深色，之后 27 帧米色，即换了人 | 145–166 | 90–116 |
| 闭环：v11 / 低延迟版 | 倒地（2.16 / 2.02 s），参考关节速度峰值 34 rad/s | **未倒地**，RMSE 0.157 / 0.146 rad | 倒地（2.10 / 1.98 s），参考骨盆最低降到 0.18 m |

- 锁定 P1 和锁定 P0 的两次运行，目标在 118 帧里相距至少 0.72 m，从未落到同一个人身上。两段躯干亮度区间也不重叠（145–166 对 90–116）。亮度这条证据不依赖几何计算。
- 人工核对了叠加图：P0 的第 64–116 帧、P1 的第 32–60 帧，被采用的机位都在正确的人身上。P0 被 P1 挡住时，D001 检测不到他，这个机位就没有被采用。
- 锁定 P1 时，闭环 RMSE 与 AdvancedTake 真实动作（0.126–0.168 rad）在同一区间，都高于配置阈值 0.12。"未倒地"不等于模仿成功。
- 身份歧义判定在 MAMMA 上一次也没有触发：两人躯干最近也有 0.72 m，另一个人从未进入目标 0.25 m 的门限。歧义、遮挡、丢失、点选过期这几条逻辑只在合成测试里验证过。

## 结果：AdvancedTake 单人回归

条件与原链路相同：同一份标定 `cameras_rgbonly.json`，同样的 S2/S3 参数，滞后 6；S1b 用自动选择模式。

- 从全部候选里按面积×置信度挑出的关键点，与已验收的 S1 缓存完全一致，差值为 0（共 8968 帧）。
- 5 个 Take 都在第 3 个时间槽自动锁定被试。按 S1 的记录，背景旁观者主要只在 44310277 和 44310284 两个机位被检到，达不到 3 机位建轨的条件；自动选择在 5 个 Take 都成功了，说明他没有挡住锁定。旁观者有没有形成轨迹，本次没有单独记录。
- 3D 输出与原链路逐槽相同的比例：002 为 347/347，006 为 453/454，007 为 404/405，008 为 438/438，012 为 500/513。
- 原始 3D 指标的变化（Procrustes / 逐帧 PA / 骨段方向）都很小，不超过 0.18 mm、0.07 mm、0.06°。最差的是 Take_012（35.72 → 35.90 mm）。这一段是快速拍手，有 10 个槽某个机位的整体误差超过门限，被 S1b 整个剔除；原链路的 S2 共识能在关节层面利用这个机位。
- 前 2 个槽在等轨迹确认，没有输出，观测比例从 1.00 降到 0.99。

## 延迟

本机桌面在后台负载下，用交替计时测 3 遍 × 120 帧，图像解码不计入。

| | 中位 | P95 |
|---|---|---|
| 现有 S1（4 机位 YOLOX，加 4 个裁剪做 RTMW） | 55 ms | 115 ms |
| S1 全候选 + S1b（平均 9 个候选，RTMW 分两批） | 72 ms | 130 ms |
| 逐帧配对差值 | **+12 ms** | +65 ms |

S1b 的分组和跟踪本身中位 0.5–0.9 ms，增量主要来自第二批 RTMW。负载较低的第一次运行里，检测 16 ms、全候选 RTMW 16 ms。这些数受桌面后台程序（网盘、浏览器）影响很大，不是实时系统上的测量。

## 不能声称的内容

- 身份正确性没有标注支撑，依据是几何连续性、躯干颜色、两次运行的分离和人工核对。
- 只有一个 4 s 片段、两个人。
- 工作区里多于一人时，必须由操作者指定目标；自动模式只适用于工作区内只有一个人的情况。
- P0 躺地被挡住时，B001 和 D001 都检测不到他，只剩相对的 A001 和 C001 两个机位，几何条件差（髋宽变异系数 19%），但状态仍是 TRACKING。S2 的协方差没有传给下游，也没有"按预测框补裁"的回退。
- S1b 只解决"跟谁"，不解决"该不该模仿"。目标倒地时机器人照样倒地，这需要一个独立的动作域门限模块。
- 延迟中位增加约 12 ms。
