# 50 Hz 参考生成与控制器分离：2026-11-09

## 结论

1. **换用 SONIC low_latency（0 预览）是本轮唯一一致的改进。** 参考不变，只换控制器：5/5 段物理手臂误差下降，均值 17.59°→16.15°；腿 12.49°→12.05°；脚滑 0.113→0.095 m/s；终点偏差 0.576→0.269 m；全程平均位置偏离 5/5 段下降。两轮独立运行（30 次、20 次）结果逐位一致。
2. **三种修正 30→50 Hz 交付阶跃的方法都没有带来收益**，按负结果保留：每拍重解、每拍重解＋8 rad/s 历史约束、按 S3 自身速度模型预测到控制拍。交付阶跃不是当前精度瓶颈。
3. **发现并修复一个计时污染问题：** Windows 对后台进程的节能调度让进程运行约 3 秒后整体降速约 5 倍，IK p50 从 1.3 ms 变成 11.9 ms。关闭后全程稳定在 p50 1.32 ms、p99 1.9 ms。此前在长时间后台进程中测得的毫秒数需要按此复核。

未改动主线默认值（`s6_closed_loop.default_policy` 仍为 `sonic_v11`）。所有片段此前都看过，不是盲测；只有仿真，没有实机。

## 失效分析

- **50 Hz 重解无效的原因**：新观测仍以 30 Hz 到达，IK 每次在新观测到达的那一拍就收敛，阶跃原样保留（交付加速度 p99 不变）。
- **历史约束是负结果**：交付层确实满足 8 rad/s、60 rad/s²，但参考跟不上真人动作；Take_012 手臂误差 21°→55°。8 rad/s 低于真人快速手臂动作所需，参考滞后后落入错误构型。这些限值不是 G1 认证值。
- **速度预测是负结果**：预测把滤波器速度噪声直接加到参考上，交付加速度反而升高，v1.1 下脚滑升至 0.140 m/s。
- **0.18 s 预览**：不计延迟时手臂最好（22.71°），计入延迟后变差（27.13°），延迟抵消了收益。

## 尚未解决的风险

low_latency 在 0 预览时看到的是重复当前帧的静止参考窗口，这不在其训练分布内（见 `docs/技术概览.md`）。本轮仿真没有暴露问题，但上实机前必须单独验证；也需确认它可由所用 G1 EDU 的 SDK/固件运行。`SonicPolicy.name` 固定为 `sonic_v11`，用 low_latency 配置运行时报告里的控制器标签会错误，切换默认前需要修正。
