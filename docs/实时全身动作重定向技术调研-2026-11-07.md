# 实时全身动作重定向技术调研：2026-11-07

## 结论

不存在一个已经公开、装上当前电脑就能保证满足本项目所有要求的“最佳算法”。当前最适合当作**下一代技术路线**的是：**机器人语义目标 + 物理专家生成监督 + 因果流式神经重定向（SMR 类方法）**；参考执行端用能跟踪 G1 根部路线的全身跟踪策略。短期基线保留关键点 IK/GMR 类几何重定向，继续完善多相机实时输入和端到端计时。

### 2026-11-07 补充：已找到更贴近当前目标的现成组合

前文遗漏了一个重要感知候选。**RT-COSMIK + Teleopit/GMR** 是目前更值得先做本项目独立验证的路线：前者解决多视角 RGB 到带世界位姿的人体全身关节模型；后者提供 G1 GMR 映射与全身跟踪运行时。它不是已集成的一键方案，但比“从稀疏关键点猜身体朝向，再把自定义 IK 称为视觉版 GMR”更接近真实系统接口。

这也回答“是否要先提取人体点云”：**不必把稠密点云作为中间表示。**GMR 和跟踪控制器需要有语义的骨架/刚体位姿及根部轨迹；RT-COSMIK 的多视角人体 3D 标志与拟合人体模型正好在这些表示上工作。四台 RGB 相机能做三角化/多视图人体拟合，但稠密人体点云需额外多视图立体重建，仍不能直接给出左右关节身份、骨盆朝向或被遮挡肢体状态，可能增加成本而不增加所需约束。

推荐优先级因此调整为：**先在隔离运行目录回放同一批真实多视角片段，评估 RT-COSMIK 输出和人体可视化；随后接一个只传人体状态的 Teleopit/GMR 流式桥；最后固定同一 WBC 与物理参数比较现有 IK 和原生 GMR。**先报告每阶段的 p50/p95/p99、帧龄、漏帧、左右腿对应、骨盆路径、步态相位、关节误差、滑移和存活率，再决定是否替换现有链路。

明确限制：RT-COSMIK 实时演示的 4 路标称工况是 720p/40 fps，论文评测处理率为 43 Hz；本项目计划 50 Hz 工业相机，因此需在 RTX 4090 和真实相机链路上测尾延迟，不能由 GPU 型号推断已达 50 Hz。其人体模型关节角和骨段位姿也不等于完整手掌/脚掌方向或真实接触力。标定须避免给人体佩戴任何标记；该项目示例标定 wand 上的 ArUco 只用于相机到场地坐标的离线标定，可用场地测量/标定方案替换，且运行时不应保留标记物。G1 EDU 实机运行仍需具体模型、限位、时钟、反馈与独立急停验证。

本补充仅基于公开仓库/论文资料核实；尚未安装或运行这两个上游项目，不构成本机视觉、仿真闭环或实机验证。

推荐的职责划分：

```text
同步多相机 RGB
    -> 经实测支持多人/遮挡的数据关联与 3D 姿态
    -> 人体语义状态 (骨盆平移/朝向的可观测部分、双侧肢段、躯干、置信度、足接触候选)
    -> 因果、G1 专用的机器人语义重定向器
    -> 机器人根部 + 29 关节参考
    -> 根部和全身跟踪 WBC
    -> 500 Hz 独立设备通信、安全门与急停
```

腿部和骨盆是行走依据。不得让双腕动作单独产生步态，也不得向不可观测的骨盆俯仰、掌/足完整朝向填入看似测量的值。机器人能否保留真人动作关系与控制器能否稳定执行，应分开评分。

## 本机条件与实测边界

本机实查：Intel Core i9-13900KF（24 核、32 线程）、NVIDIA RTX 4090（24 GB）、128 GiB 内存。仓库规定的相机方案是四机位起步、最多六机位、50 Hz 同步曝光；G1 控制链路计划 500 Hz。

按 50 Hz 视觉输入，一个新观测每 20 ms 到达一次；控制器预览可能另外要求已接收的将来参考，因此预览长度在因果系统中等价于引入相应等待。重定向器耗时只占一部分：必须分别记相机曝光时间、图像/检测/三角化、重定向、缓存/预览、WBC 输出、机器人响应。只有检验时钟戳、帧龄、deadline miss 与端到端尾延迟，才能说整条链路实时。

仓库已有依据：关键点 IK 单帧 p50 约 1.28 ms、p95 约 1.89 ms，但它是在 30 Hz、已保存关键点的离线回放中测得，不能证明实时多相机管线；S3 One-Euro 在既有 30 Hz 真人数据评测中造成约 67 ms 典型滞后。另一个既有 S1/S1b 回放，4 路当前基线约 55 ms p50 / 115 ms p95，全候选约 72 / 130 ms，显示视觉而非 IK 是当前实时瓶颈。手册估算批处理/追踪式 S1 可达 10 ms 属于目标设计值，尚不是本链路 4–6 相机实测值。

GMR README 在 i9-13900K 上公布 35–45 FPS，即 22–29 ms/帧；该主机和当前 13900KF 属同一代同一核心数，但并非我们机器的对照实测。即使采用有利端，也不能证明在视觉计算并发时有稳定 50 Hz 余量。

## 推荐路线

### 现在先用什么

**继续现有 27 点→逐帧 CPU IK 作为“实时可解释 baseline”，不要继续尝试把新加的 QP 权重当成最佳算法。** 最近五段×五分支试验中，最新三项组合让平均物理手臂方向误差从 20.46° 降到 18.93°，但腿误差略增、滑移从 0.0612 增至 0.0815 m/s、参考终点偏差从 0.307 增至 0.476 m；没有整体胜出。该结果说明优化器快，不能说明它已足够像人或适合真机。

**可立即实施的首选验证组合是“现有关键点 IK / GMR 原生逐帧重定向 + MimicLite v1.1”，而不是立即复刻 SMR 全部训练。** 先用同一参考更换 WBC，再比较两种重定向参考，避免同时更换前端、重定向和控制器导致无法定位收益。GMR 的当前上游 commit 与仓库固定 commit 相同，不能把拉取同一个版本称为算法升级。原项目“GMR 不能实时”指的是前置 EasyMocap 整段 SMPL-X 拟合链路，而非 GMR 的逐帧 `retarget()` 本身。沿用离线拟合结果不会满足直播因果性；把未知旋转补成固定值也不构成可靠输入。

下一步先修系统层 deadline：把 4–6 路检测改为批处理/稳定目标时的切图推理；所有几何和滤波参数使用曝光硬件时间戳；单独测 S1/S2/S3 的 p50/p95/p99.9。S3 当前约 67 ms 相位滞后，不适合继续靠放慢动作或删除低通掩盖。新滤波器以肢段方向/长度和人体根为变量，速度自适应但不引入零相位/非因果滤波，并在同一硬件时间戳下量化相位与噪声。CPU 保留 Mink；4090 不应为约 1 ms 的小 IK 搬数据或增加 GPU 同步。

### 最值得研发的“最好技术”

**以 SMR 为架构参照，做项目自有、G1 专用、因果的物理监督语义重定向器；不要等待一个尚未公开的 checkpoint，也不要声称直接复现其 97%。** SMR 的设计与要求最吻合：人类语义目标先确定“想做什么”，G1 物理 expert 通过接触/关节限制找“G1 能怎样做”，严格因果 student 学 robot reference。我们的语义输入可从 50 Hz 视觉结果得到：骨盆平移和可观察朝向、左右上/前臂与大腿/小腿方向、躯干姿态、源步频/支撑候选、关节/关键点置信度和时间戳。不可观测项必须显式标记 unknown，并通过训练/推理不确定性而非任意先验强迫补成已测姿态。

这属于后续研究方案，不是本次已实现的方法。公开 SMR 与 MimicLite 的实验涉及多 GPU 训练；单张 4090 可以合理预期承担小型 student 的推理及小规模训练试验，但不能据此承诺完整专家生成、WBC 从零训练或论文质量复现。近期应优先使用已发布的 WBC checkpoint，并等待/获取 SMR 可复现实现；如自行研发，先在少量动作上核算 teacher 数据成本与训练收敛，再决定是否扩展。

建议 12.7M 级因果网络只作为**起点假设**：使用 KV cache 的有界历史上下文、每帧 50 Hz 输入，先输出关节、骨盆轨迹、速度和不确定性，再让已验证的 G1 WBC 执行；在低置信度、OOD 或丢帧时退回经过验证的 hold/safe state，不凭网络继续猜新动作。模型先在 workstation RTX 4090 上训练/推理比较；推理 model-step 目标设 p99 < 2 ms（约占 20 ms 感知帧周期十分之一），最终目标仍看 end-to-end p99.9 deadline，而不是只看网络均值。

teacher 以源动作语义＋G1 物理模型产生候选参考并在冻结 G1 WBC 上闭环筛查，只用动作语义/动力学执行判据作为训练标注；student 输入必须是实际可感知的 pose streams，训练加入按本系统协方差、遮挡/缺测和同步误差采样的退化观测。**仿真状态不能进入在线感知输入，也不能把理想 mocap label 的表现说成 RGB 验证。** 按动作类别（正常步行、转身、蹲/弯腰、单侧摆臂）划分训练/验证/未见评测片段，保存失败样本；按骨盆路径、同侧关节角/速度、支撑相位、世界航向、事件关系、运动幅度与 fall/skating 一起验收。此项目留出真人集仅 3 段，研究验证还需不参与调参的新动作/新速度。

下游控制优先补做 MimicLite 与现有 SONIC 的等条件 G1 对比：先将同一组离线 reference 分别送到两个控制器，确认根部路线与双腿跟随能否改善，再把同一因果 student 接入胜出的控制器。MimicLite 的 80 ms 预览可由因果 student 在线缓冲已产生的机器人未来参考，代价是总延迟至少增加该窗口；使用算法预测未来不能把延迟计作零。SONIC v1.1 的 900 ms 未来参考合同不适合本项目的短延迟目标；当前 low-latency 版 180 ms 仍需计入整条链路。

## 工程验收门槛

硬件说“满足实时”，建议明确为：50 Hz 已同步输入，连续 30 分钟、4 路与 6 路各一轮；无算法 backlog，丢帧/观测过期的 fail-safe 明确；视觉＋滤波＋重定向 p99 ≤ 15 ms、p99.9 < 20 ms；分别报告接收到观测的时间戳、实际应用到 WBC 的帧龄与限速触发率。GPU 每个摄像机 batch 和 GPU/CPU 传输单独 profile。机器人 side 独立进程保有 500 Hz I/O、反馈、限位和硬急停；视觉线程不得阻塞安全周期。

上述 15/20 ms 是目标 deadline，不是目前已有实验已达到的成绩。随后吊架下做实体 G1 的站姿、慢步/原地踏步、短距离前进和转身，先以低动作幅度跑；实机模型/动力学、MimicLite/SONIC 选择、SDK/时钟映射、安全停止未实测前，不宣称已具备实机保证。
