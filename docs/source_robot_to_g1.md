## 2026-10-18：足部证据与触地相位审计

`pose_sim/foot_support.py` 独立接收当前脚跟/两脚趾世界位置 m、速度 m/s、位置标准差和速度协方差、足部附着校验、给定平面 Z 高度及曝光 ns，输出原人体状态契约的 `contact/swing/unknown`。`contact` 只是近地静止假设，没有测量接触力。配置为 `config/human_support.json`；平面未知时全部返回未知，运行默认仍不提供地面高度。

同一个点同时近地且可靠静止才能提供支撑证据；脚跟运动而脚趾稳定允许提供支撑。贴地滑动不能证明离地。只有全部脚部点的高度超过不确定性余量才支持摆动，不要求速度同样可观测。当前证据消失、附着失败、协方差异常、超时或证据冲突立即撤回；连续三帧确认新标签。人体位置、骨长、旋转和机器人控制没有通过这一模块修改。

`motion_control/contact_metrics.py` 仅用于评测：机器人分脚法向力 N 和体重 N → 承重转换事件，使用整数机器人 ns，分别保留初次越阈和确认时刻。初始承重、短暂单帧冲击及未知后的重现不算新触地。源端只按连续有效预测分段，不声称分段就是人的步数；首次窗口冻结、同侧一对一匹配，不扩大窗口或重复使用触地事件。无效时间/窗口拒绝，未匹配保持未匹配。

10 段、3,210 帧中的 31 次预测为 16 段连续预测（S2：5；S4：11）。S4 全部 25 次发生在 `|roll/pitch|≥0.5 rad` 首次违规之后；这个分层没有把深蹲高度当成倒地，也不是完整稳定性证明。源物理时钟窗口匹配 2/16，另行加固定 120 ms 输入延迟为 4/16；其中各有 1 个属于 S4 倾斜违规后的触地。S2 对应为 1/5 和 3/5。两套数字均为“源假设与机器人承重一致性”，不能称人体真实触地准确率。

六段缓存 RGB、864 帧、1,728 个足目标：旧标签中 1,118 个摆动及 16 个支撑改为未知；新标签共 437 个摆动、1,291 个未知、0 个支撑。人体位置/速度/形状/旋转逐值相同；未知增多主要暴露速度不确定性，不能据此宣称质量提高。早期候选把速度不可靠也用于否决离地，导致全部未知；已改为分开判定，保留该负面报告。模块 CPU 均值约 0.118 ms、P95 0.158 ms；不含图像推理或曝光时延。

## 2026-10-18：速度坐标与源相位约束的落脚规划

## 2026-10-18：有限时域退出方案预测（实验）

新增 `motion_control/recovery_rollout.py`，通过完整 G1 动力学和现有策略，比较 32 个退出方案在未来 4 秒内的结果。只在离线回放结束时启用；跟踪与观测缺失期间不调用。默认仍为 `legacy`，不会用自主恢复动作提高人体模仿评分。

本轮 10 段、3,210 帧：相较 `support_aware`，末段停止 4/10→5/10，完整模仿 0/10；原腿部/路径评分及接受量逐项相同。低照度片段末段高度 0.154→0.783 m，但质量 +10% 或摩擦 +25% 时会跌倒，不能默认启用。五个选中方案的速度扰动 20/20 通过，模型扰动 18/20 通过；仅为有限条件诊断。详见 [本轮验收](../reports/recovery-rollout-2026-10-18.json)。

| 契约 | 定义 |
|---|---|
| 输入 | 当前机器人积分状态、策略历史及已应用的 35 维参考；模型绑定的离线仿真整数 ns。世界 Z 向上，根部速度参考用水平航向坐标，关节 rad，位置 m、速度 m/s |
| 输出 | 一组制动时间、姿态过渡时间、反馈起点混合系数及退出速度增益；给原 50 Hz 限速器的参考，附候选/接触/验证报告。没有源曝光时间戳，也不输出人体脚掌旋转 |
| 预测 | 每个分支独立保存 MuJoCo 积分状态和策略历史，模型只读共享；包括 1 kHz PD、力矩上限、碰撞与接触变化。接触力超过 5 N 才记录承重，落脚位置是机器人足部刚体原点 |
| 验证 | 合批策略预测后，用实际单样本 CPU 控制器重新执行候选；未通过不能被选中。另对选中方案施加世界 X/Y 初速度 ±0.05 m/s 扰动，只作敏感性诊断，不代表校准的不确定性或实机误差分布 |
| 失败 | 已超出入口高度/倾角范围、不存在通过检查的候选，返回无方案；回放明确回退至实验性 `support_aware`，此回退可能跌倒。配置错误、模型/速率不匹配、非有限状态或推理失败则中止仿真 |
| 边界 | 假设准确机器人状态和同一物理模型；规划期间仿真时间冻结。`hardware_enabled=false`、`online_eligible=false`。不是在线 MPC、显式落脚位置优化、可靠急停或任意扰动恢复控制器 |

参数在 `config/g1_recovery_rollout.json`。32 个候选只覆盖五维退出时序/边界参数，不存在可行候选不能证明机器人无法恢复。未来接触由动力学产生，尚未直接优化落脚位置和时刻。参考 [捕获点 MPC 与踝/髋/踏步策略](https://arxiv.org/abs/2307.13243v3) 和 [Atlas 落脚时间/位置调整](https://arxiv.org/abs/1703.00477)，本模块没有复现这些论文的控制器。

设备对照：32 路合批小网络单次均值 CPU 0.556 ms / CUDA 0.511 ms，但完整直行搜索为 CPU 6.91 s / CUDA 12.30 s；这是探索性顺序测量，不作为严格加速比。剖析确认 Conv/Gemm 等在 CUDA 执行，部分形状算子在 CPU。当前选 CPU；最终七次完整搜索为 6.85–9.11 s，三个入口已失稳的案例立即拒绝。视觉 CUDA/OptiX 与环境锁不变。

& $rt.python scripts/benchmark_recovery_rollout.py --sources outputs/trajectory_study/root_path_correction/01_straight/integrated_displacement --output outputs/my_recovery_check

## 2026-10-18：轨迹约束与动力学复核

最新状态：六个渲染场景和一段 30 秒真实人体感知输入均未通过完整 G1 模仿验收。平滑、分组 jerk 限制及统一减速不能稳定改善腿部相位、平衡和根部路径；默认仍为 `rate_limit`，实验参数不成为实机参数。后文早期单段数值是历史结果，当前多场景证据见 [验收](../reports/vision-person-trajectory-2026-10-18.json)。

| 独立模块 | 输入、输出与约束 | 失败与验证 |
|---|---|---|
| `root_path.py` | 源世界 XY 位移 m、尺寸比、曝光 ns → 以首个可靠骨盆为原点的目标 XY m；Z 为目标基座高度 | 修复绝对坐标乘变化尺寸比引起的假位移；非有限数/乱序不更新状态；验证平移不变性及位置速度一致性 |
| `reference_trajectory.py` | TWIST 35 维参考及模型关节界限 → 参考位置/一阶、二阶导数；关节 rad，根部各轴单位见配置 | Ruckig 全曲线关节位置检查、速度/加速度/jerk 约束；不可行则终止仿真，不裁切曲线伪造连续性；缺失由调用方请求回站姿 |
| `offline_reference.py` | 接受的参考序列 → 分段三阶差分正则；可显式统一减速 | 使用未来数据，仅离线；不填补拒绝帧，保留原参考/路径评分。减速标明新回放时钟，保留原曝光时间 |
| `tracking_metrics.py` | 模拟关节与接触反馈 → 相位延迟、接触点切向速度 | 相位保留缺失时间，不压缩时间轴；模拟脚滑不是真人接触真值，不输入感知 |

`config/g1_reference_trajectory.json` 明确 `hardware_enabled=false`。关节参考约束不是策略输出、电机力矩、接触或平衡保证。根部前两维本身是局部速度，其“jerk”参数是该参考量的三阶导数，不能全部称为关节角 jerk。默认因果导数只用过去三次接受观测；只有显式离线数据允许未来导数。根部路径修复后，重新执行原始感知到重定向才能得到新参考；旧产物不会静默覆盖。

策略接口已与固定 TWIST2 修订核对。下一阶段应联合处理源运动接触假设、目标足底/质心约束与策略训练分布，并以原始源腿部动作评分；不能靠独立速度步态或改变评分目标制造通过。源脚掌旋转、接触真值及真实误差校准仍不足。

当前任务是人/同构人形到 G1 的全身动作模仿，允许身高和肢体比例不同。机器人应对应抬同侧腿、摆臂、转身和移动。机械臂到双腕、手势触发行走的路径已经撤下；历史 Panda 报告不是本任务验收。

## 模块与接口

| 模块 | 输入 → 输出 | 当前处理的关键问题 |
|---|---|---|
| `pose_sim/sensors.py`、`scripts/import_real.py` | 相机曝光、标定、时钟映射 → 同步图像组 | 整数纳秒精度、最近未使用帧匹配、漂移/同步预算 |
| `pose_sim/runtime.py`、`pipeline.py` | 多相机无标记 RGB → COCO17 2D/3D 与质量 | CUDA 执行证据、重投影异常、多视角退化、缺点保持未知 |
| `motion_control/humanoid.py` | 3D 身体点 → 29 关节全身参考及观测掩码 | 肢段方向与尺寸重定向、左右对应、因果滤波、关节限位、多解正则；手臂缺失不打断可靠腿部 |
| `motion_control/root_tracking.py` | 源骨盆路径、机器人世界里程计 → 速度/朝向纠偏 | 源/目标坐标对齐；目前路径跟踪误差仍超标 |
| `motion_control/twist.py` | 全身参考、IMU、29 关节反馈与历史 → PD 目标 | TWIST2 全身动作策略；腿部参考参与网络输入，不另造速度步态 |
| `motion_control/g1_command.py` | 具名限幅目标、模型与时钟信息 → 模拟接收器 | 型号/顺序绑定、序号、TTL、有限数检查；无实机发送 |
| `motion_control/humanoid_replay.py` | 带延迟的观测流 → 物理反馈、指令、并排视频及验收 | 50 Hz 策略、1 kHz 物理、120 ms 注入延迟、遮挡/丢包退回站姿 |

坐标采用右手世界 Z 向上，人体/机器人局部 X 向前、Y 向左，长度 m、角度 rad、时间整数 ns。模型/关节/PD 参数固定在 `config/g1_twist.json`，资产 URL、Git 修订及 SHA256 在 `assets/humanoid/manifest.json`。视觉与控制的运行环境分别冻结；RTX 4090 执行 OptiX 渲染和 CUDA 图像推理，低维 IK 与约 0.2 ms 的跟踪策略留在 CPU。

## 已知假设与未解决项

COCO17 没有脚趾、脚跟和手掌朝向，也不足以唯一分离骨盆倾斜与腰部倾斜。当前明确使用直立骨盆、脚掌平放、腕中立和躯干倾斜分配到腰部的先验；不是视觉测出了这些旋转。手臂/躯干不可靠时使用中立先验并输出有效性掩码。腿部关键点缺失时撤回整段动作，过期姿态不会获得新时间戳。

同构人形、尺度改变、左右肢体对应、抬手不产生行走、局部遮挡、滤波回滚、策略历史顺序与命令过期已有回归。62 项测试在机器人环境通过，视觉环境跳过 6 项 MuJoCo 测试。

当前整体验收失败：主要髋膝动作相关性约 0.75–0.91，腿部参考跟踪 RMSE 约 0.24 rad；骨盆路径 P95 误差约 0.77 m。不同策略检查点和控制频率比较没有解决此问题。需要改进脚掌/接触观测、人体到机器人接触一致的重定向与运动策略适配，不能仅降低验收阈值。尚未验证多种动作、多人、真实多相机和外观不同的人形机器人。

源示例是 CesiumMan 的行走周期，并在渲染端添加向前平移；动画帧率在 glTF 导入前设置。该平移参数只改变画面，不输入感知或控制。生成图像不是实拍精度基准。骨骼真值只用于独立视觉评估。

## 硬件迁移

当前选择公开 29 自由度 G1 描述，不能据此推断用户 EDU 的具体硬件配置。物理接入还需核对关节/电机槽位、腰部版本、负载、相机外参、时钟、IMU/关节反馈、世界里程计、延迟、摩擦及停止策略。此处的全身低层策略需要独占电机控制；不能与另一行走控制器同时写电机。

模拟指令包含位置、零目标速度、PD 增益、零前馈力矩、力矩上限、序号、TTL、模型哈希和时钟域。当前没有 DDS 网络发送、设备 CRC/ACK 或硬件急停验证。无独立实机 watchdog 的程序不能宣称已经准备好直接上机。
